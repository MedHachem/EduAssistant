# EduAssistant — frontend

Angular 22 (standalone components, signals, zoneless).

## Commands

```bash
npm install
npm start        # ng serve → http://localhost:4200 (proxies /api → http://localhost:8080)
npm run build
npm test         # Vitest
```

## Knowledge Base review (`/admin/ai-pipeline/knowledge-base`)

Prototype for manually validating the KnowledgeItems generated by the Python pipeline.

- **Input (read-only):** `npm start` / `npm run build` first run `scripts/sync-knowledge.mjs`, which copies
  `data/output/knowledge/*.json` → `public/knowledge/` and `data/output/page_images/*.png` → `public/page-images/`
  (both gitignored). Nothing is ever written to `data/`. Re-run `npm run sync:knowledge` after regenerating.
- **Review state:** kept separately in `localStorage` (`edu.knowledge-review.v1.<chapter_id>` →
  `{ [itemId]: { status, reviewed_at } }`) and overlaid on the generated `validation_status` in the UI.
- Math is rendered with KaTeX; the **Raw** toggle shows the untouched source strings.
- Shortcuts: `V` validate · `R` reject · `U` undo · `J`/`↓` next · `K`/`↑` previous.

## Student chat — AI Teacher (`/app/chat`)

UI only for now. `environment.chat.mock = true` uses `MockChatTransport`, which streams canned answers
locally with the same protocol as the real server. Set it to `false` to use `WebSocketChatTransport`
(`environment.chat.wsUrl`, default `/ws/chat`, proxied to `ws://localhost:8080` in dev), which provides
auto-reconnect with exponential backoff and queues messages while disconnected.

Expected WebSocket protocol (JSON frames, see `features/client/chat/chat-protocol.ts`):

```
client → server
  { "type": "user_message", "conversationId", "messageId", "content" }
  { "type": "cancel",       "conversationId", "replyTo" }            // stop answering messageId=replyTo

server → client
  { "type": "assistant_start", "conversationId", "messageId", "replyTo" }
  { "type": "assistant_delta", "conversationId", "messageId", "delta" }   // text chunk to append (Markdown + $LaTeX$)
  { "type": "assistant_end",   "conversationId", "messageId" }
  { "type": "error", "conversationId"?, "messageId"?, "message" }
```

Ids are UUIDs generated by the client for conversations and user messages, and by the server for answers.
Conversations are kept in `localStorage` (`edu.chat.v1.<userId>`) until the backend owns history.

## Auth

Auth is bypassed (`environment.authBypass = true`): the login page picks a mock user
(ADMIN or CLIENT) and stores it in `localStorage`. The guards already enforce roles, so
wiring the real JWT login later only means changing `AuthService.login`.

## Data Injection — document library

`/admin/data-injection` (Upload) shows **Official Books**, **Official Exams** and **Official Tests** plus the whole
library; `/admin/data-injection/:type` is the upload form (PDF → information → correction for exams/tests → visibility).
Fields are declared in `core/documents/document-types.ts`; forms are generated from it.

A document is **DRAFT** (admins only) or **PUBLISHED**. Published books appear to students in `/app/courses`
and open in the course viewer (`/app/courses/:id`, browser PDF viewer).

`environment.documents.mock = true` → `LocalDocumentsApi`: metadata in `localStorage` (`edu.documents.v1`),
PDFs in IndexedDB (`edu-documents`), so the whole flow works without a backend (per browser only).
Set it to `false` for `HttpDocumentsApi`, which expects:

```
GET    /api/admin/documents                           → LibraryDocument[]
POST   /api/admin/documents        multipart:  file (PDF), correction? (PDF),
                                               metadata (JSON: { type, status, ...fields })
                                                     → LibraryDocument        (PDF stored in Azure Blob Storage)
PATCH  /api/admin/documents/{id}   { status }        → LibraryDocument
DELETE /api/admin/documents/{id}                     → 204                    (also deletes the blobs)
GET    /api/courses                                  → LibraryDocument[]      (published books only)
GET    /api/courses/{id}                             → LibraryDocument
GET    /api/documents/{id}/file-url?which=file|correction → { url, expiresAt } (short-lived read-only SAS URL)
```

The browser never talks to Azure directly and never holds storage keys: the backend uploads the blob and
hands out read-only SAS URLs for viewing. The blobs must be served with `Content-Type: application/pdf`
(and `Content-Disposition: inline`) so the viewer can display them.
